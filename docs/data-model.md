# مدل مفهومی سؤال‌ها و روابط

وضعیت: مبنای اولیه برای طراحی داده و پیاده‌سازی

## هدف پروژه

ساخت سیستمی برای تولید سؤال، بدون اتکا به استادان کنکور برای طراحی سؤال. سیستم سؤال‌های موجود را از منابع مشخص استخراج و سازمان‌دهی می‌کند و از آن‌ها برای ساخت سؤال‌های جدید استفاده می‌کند.

دامنهٔ منابع شامل آزمون‌های گاج، قلم‌چی، گزینه‌۲، سنجش، ماز و کنکور اصلی است. دامنهٔ آموزشی شامل پایه‌های دهم، یازدهم و دوازدهم رشته‌های ریاضی و تجربی است.

## اصل مدل‌سازی

هر سؤال یک موجودیت مستقل است. مدل ارتباط سؤال‌ها «پرنت–چایلد» و درختی نیست؛ ارتباط‌ها می‌توانند چندبه‌چند باشند.

سه مفهوم زیر باید مستقل از یکدیگر نگهداری شوند:

1. ارتباط با سؤال‌های کنکور
2. منشأ تولید سؤال
3. دسته‌بندی آموزشی

## ۱. سؤال‌های کنکور مرتبط

نام مفهومی: سؤال‌های کنکور مرتبط  
نام فنی پیشنهادی رابطه: `related_exam_questions`

این رابطه مشخص می‌کند یک سؤال با کدام سؤال‌های کنکور از نظر مفهوم، الگو یا روش حل مرتبط است.

قواعد:

- هر سؤال می‌تواند به صفر، یک یا چند سؤال کنکور مرتبط باشد.
- هر سؤال کنکور می‌تواند با چند سؤال دیگر مرتبط باشد.
- نداشتن سؤال کنکور مرتبط، مانع ثبت یا نگهداری سؤال نیست.
- یک سؤال ترکیبی می‌تواند هم‌زمان به چند سؤال کنکور مرتبط باشد.
- مرتبط‌بودن با یک سؤال کنکور، به معنی تولیدشدن از روی آن نیست.

## ۲. سؤال‌های مبنای تولید

نام مفهومی: سؤال‌های مبنای تولید  
نام فنی پیشنهادی رابطه: `generation_sources`

این رابطه مشخص می‌کند سیستم واقعاً از کدام سؤال‌ها برای ساخت یک سؤال جدید استفاده کرده است.

قواعد:

- یک سؤال تولیدشده می‌تواند چند سؤال مبنای تولید داشته باشد.
- یک سؤال موجود می‌تواند مبنای تولید چند سؤال جدید قرار بگیرد.
- سؤال مبنای تولید لزوماً سؤال کنکور نیست؛ می‌تواند از منابع مؤسسات نیز باشد.
- منشأ تولید باید مستقل از ارتباط با سؤال‌های کنکور ثبت شود.
- ارتباط مفهومی یا شباهت، برای ثبت یک سؤال به‌عنوان مبنای تولید کافی نیست.
- برای سؤال‌های واردشده از منابع، نباید بدون شواهد رابطهٔ منشأ تولید ایجاد شود.

## ۳. دسته‌بندی آموزشی و مباحث مرتبط

نام مفهومی: دسته‌بندی آموزشی و مباحث مرتبط

سؤال‌ها باید به ساختار آموزشی مرتبط شوند؛ از جمله:

- رشته
- پایه
- کتاب درسی
- درس
- فصل
- مبحث

قواعد:

- دسته‌بندی آموزشی از ارتباط سؤال‌به‌سؤال مستقل است.
- مدل باید سؤال‌های ترکیبی را پشتیبانی کند؛ یک سؤال ممکن است چند مبحث یا فصل را پوشش دهد.
- ارتباط آموزشی سؤال نباید صرفاً از سؤال‌های کنکور مرتبط یا سؤال‌های مبنای تولید به ارث برده شود.
- جزئیات ساختار و سلسله‌مراتب کتاب، درس، فصل و مبحث در طراحی بعدی مشخص می‌شود.

## مثال

یک سؤال تولیدشده می‌تواند هم‌زمان:

- از روی دو سؤال قلم‌چی ساخته شده باشد؛ این دو سؤال، مبنای تولید هستند.
- به سه سؤال کنکور مرتبط باشد؛ این سه سؤال، سؤال‌های کنکور مرتبط هستند.
- دو مبحث از فصل‌های مختلف را پوشش دهد؛ این موارد، دسته‌بندی آموزشی سؤال هستند.

این سه مجموعه نباید به‌جای یکدیگر استفاده شوند.

## قواعد پیاده‌سازی برای ایجنت

- از `parent_id` یا یک ساختار درختی به‌عنوان مدل اصلی ارتباط سؤال‌ها استفاده نکن.
- روابط سؤال‌های کنکور مرتبط و سؤال‌های مبنای تولید را چندبه‌چند طراحی کن.
- سؤال بدون ارتباط با کنکور را معتبر بدان.
- شناسهٔ مستقل هر سؤال را حفظ کن؛ سؤال مرتبط یا تولیدشده، زیررکورد سؤال دیگری نیست.
- منشأ تولید را با شباهت یا ارتباط آموزشی اشتباه نگیر.
- بدون شواهد، رابطهٔ منشأ تولید نساز.
- نام‌های فنی این سند پیشنهادی‌اند؛ شکل جداول و API پس از انتخاب استک تعیین می‌شود.

## معیارهای پذیرش مدل

- [ ] ثبت سؤال بدون سؤال کنکور مرتبط امکان‌پذیر است.
- [ ] اتصال یک سؤال به چند سؤال کنکور امکان‌پذیر است.
- [ ] اتصال چند سؤال به یک سؤال کنکور امکان‌پذیر است.
- [ ] ثبت چند سؤال مبنای تولید برای یک سؤال جدید امکان‌پذیر است.
- [ ] سؤال‌های مبنای تولید می‌توانند با سؤال‌های کنکور مرتبط متفاوت باشند.
- [ ] ثبت چند مبحث یا فصل برای سؤال ترکیبی امکان‌پذیر است.
- [ ] تغییر روابط کنکور، منشأ تولید یا دسته‌بندی آموزشی، دو رابطهٔ دیگر را خودکار تغییر نمی‌دهد.

## تصمیم‌های باز

این سند دربارهٔ موارد زیر تصمیم قطعی نمی‌گیرد:

- استک فنی و ساختار فیزیکی پایگاه داده
- شیوهٔ تشخیص و تأیید ارتباط سؤال‌ها
- روش استخراج سؤال‌ها از فایل‌های منابع
- روش تولید سؤال و اعتبارسنجی سؤال و پاسخ
- جزئیات ارجاع پاسخ به نسخه و صفحهٔ کتاب درسی
- وضعیت مجوز استفاده و انتشار محتوای منابع
