# معیارهای پذیرش اولیه

وضعیت: فقط معیارهای مدل مفهومی سؤال‌ها و حلقهٔ تولید و داوری روشن‌اند. معیارهای کل محصول هنوز کامل نیستند.

## معیارهای مدل سؤال

- [ ] سؤال بدون سؤال کنکور مرتبط قابل ثبت باشد.
- [ ] یک سؤال بتواند به چند سؤال کنکور مرتبط شود.
- [ ] یک سؤال کنکور بتواند با چند سؤال دیگر مرتبط شود.
- [ ] سؤال جدید بتواند چند سؤال مبنای تولید داشته باشد.
- [ ] سؤال‌های مبنای تولید بتوانند از منابع مؤسسات باشند و الزاماً سؤال کنکور نباشند.
- [ ] مبنای تولید و سؤال کنکور مرتبط مستقل از هم ثبت شوند.
- [ ] سؤال ترکیبی بتواند چند مبحث یا فصل مرتبط داشته باشد.
- [ ] تغییر یکی از سه نوع رابطه، دو نوع دیگر را بدون درخواست صریح تغییر ندهد.
- [ ] صرف ارتباط یا شباهت سؤال‌ها، رابطهٔ منشأ تولید ایجاد نکند.
- [ ] فیلدهای کنترلی (`status`, `judge_score`, `judge_reasoning`, `solver_answer`, `solver_agreement`, `novelty_score`, `verification_method`, `reject_reason_codes`, `change_type`, `cost`) برای سؤال تولیدشده ذخیره و خوانده شوند.
- [ ] ارجاع به تکه‌های کتاب درسی در جدول `textbook_references` به‌همراه نمرهٔ شباهت ذخیره شود.
- [ ] فیلدهای تصویر (`has_figure`, `figure_asset`) برای سؤال‌های استخراج‌شده ذخیره شوند.
- [ ] فیلدهای تأیید انسانی (`human_verified`, `human_verified_by`, `human_verified_at`) در صورت فعال بودن تنظیمات ثبت شوند.
- [ ] ساختار مستقل `question_set` با ارتباط چندبه‌چند و ترتیب (`position`) بدون ایجاد وابستگی والد–فرزندی عمل کند.

این موارد برای تطبیق با `data-model.md` هستند و به معنی تصمیم دربارهٔ UI، API یا ساختار جداول نیستند.

## معیارهای حلقهٔ تولید و داوری

### چک‌لیست الزامات اجرایی حلقه
- [ ] **آزمون طلایی:** Solver روی سؤال‌های کنکور واقعی با کلید رسمی ارزیابی شود و نتیجه مستند شود.
- [ ] Judge روی همان مجموعهٔ آزمون طلایی ارزیابی شود و عملکرد آن ثبت گردد.
- [ ] وضعیت `approved` در API و خروجی به‌عنوان «تأیید خودکار هوش مصنوعی» برچسب‌گذاری شده باشد.
- [ ] اگر `require_human_verification=true`: فقط سؤال‌های `human_verified=true` در خروجی نهایی ظاهر شوند.
- [ ] اگر `require_human_verification=false`: سیستم صریحاً اعلام کند خروجی تأیید انسانی نشده.
- [ ] سقف تکرار رعایت شود.
- [ ] سؤال با چند پاسخ صحیح رد شود.
- [ ] سؤال تکراری رد شود.
- [ ] کد ناامن اجرا نشود (sandbox).
- [ ] Judge یک پاسخ غلط را رد کند (با سؤال کنترل شده).

### سناریوهای تستی مفهومی
- [ ] **تست داوری پاسخ نادرست:** Judge یک پاسخ غلط را رد کند (با سؤال کنترل‌شده).
- [ ] **تست چند پاسخ صحیح:** سؤال با چند پاسخ صحیح کد `multiple_answers` بگیرد و رد شود.
- [ ] **تست سؤال تکراری:** سؤال تکراری کد `duplicate` بگیرد و رد شود.
- [ ] **تست سقف تکرار:** سقف تکرار رعایت شود و سؤال با وضعیت نهایی ذخیره شود.
- [ ] **تست امنیت Sandbox:** کد ناامن در Sandbox اجرا نشود (یا خطا برگرداند).
- [ ] **تست ارزیابی آزمون طلایی:** آزمون طلایی اجرا شود و نتیجه مستند شود.

## معیارهای هنوز نامشخص

- دقت قابل‌قبول استخراج متن، فرمول، تصویر و گزینه‌ها: نمی‌دانم؛ اطلاعی ندارم.
- آستانهٔ عددی قبولی Solver و Judge در آزمون طلایی: باز.
- میزان شباهت یا تفاوت مجاز با سؤال مبنا (آستانهٔ `novelty_score`): باز.
- صحت و جزئیات ارجاع به کتاب: نمی‌دانم؛ اطلاعی ندارم.
- زمان پاسخ، حجم پردازش و سقف هزینهٔ قابل‌قبول: باز.
- جریان‌های کاربری لازم برای پذیرش نسخهٔ اول: نمی‌دانم؛ اطلاعی ندارم.

## شیوهٔ استفاده

برای معیارهای روشن، تست رفتار واقعی مطابق `../AGENTS.md` طراحی کن. برای معیارهای نامشخص، عدد یا شرط قبولی ساختگی تعیین نکن؛ ابتدا تصمیم لازم را بگیر.
