# نقشهٔ راه

وضعیت: فازبندی کلی تعیین شده؛ جزئیات تسک‌ها و زمان‌بندی هنوز باز است.

## کارهای انجام‌شده

- آماده‌سازی `AGENTS.md` برای قواعد کار ایجنت، پلن، تست، گزارش و Git
- آماده‌سازی `data-model.md` برای مدل مفهومی سؤال‌ها و روابط
- تهیهٔ مستندات محصول، محدودهٔ MVP، ورود سؤال، تولید سؤال، معیارهای پذیرش و معماری
- انتخاب استک فنی (Python/Django/PostgreSQL)
- طراحی حلقهٔ تولید و داوری تخاصمی

---

## فاز ۰: طراحی مدل داده و ورود داده

### هدف

آماده‌سازی زیرساخت داده برای دریافت، ذخیره و ایندکس سؤال‌ها و کتاب‌ها.

### آزمایش امکان‌سنجی (پیش‌شرط بقیهٔ فاز ۰)

پیش از پیاده‌سازی مدل‌های پایگاه داده و خطوط لوله، یک آزمایش امکان‌سنجی تجربی بر روی سه فایل نمونه انجام می‌شود:
- **سه فایل نمونه:** یک کتاب درسی متنی (دیجیتال)، یک دفترچهٔ کنکور استاندارد، و یک نمونهٔ اسکن‌شده.
- **موضوعات آزمایش:** مقایسهٔ روش‌های استخراج متن، ارزیابی مدل‌های Embedding مختلف، سنجش کیفیت پارس و حفظ فرمول‌های LaTeX، و تست مدل ویژن در تشخیص و تفکیک سؤال‌های تصویردار.
- **معیار پایان آزمایش:** انتخاب حداقل یک روش استخراج قابل‌اتکا و تعیین قطعی یک مدل Embedding و ابعاد وکتور آن.
- **الزام وابستگی:** بقیهٔ تسک‌های فاز ۰ مشروط به خروجی و نتیجهٔ این آزمایش امکان‌سنجی هستند.

### خروجی‌های مورد انتظار

- مدل‌های Django مطابق `data-model.md`
- خط لولهٔ استخراج متن از PDF (حداقل برای PDF متنی)
- تکه‌بندی و embedding متن کتاب و سؤال‌ها
- ذخیره در PostgreSQL + pgvector
- management command برای آپلود و پردازش PDF
- Docker Compose برای اجرای محلی

### معیار پایان

- حداقل یک کتاب درسی و یک دسته سؤال کنکور با موفقیت وارد و ایندکس شده باشد.
- جستجوی برداری نتایج معنادار برگرداند.
- مدل داده تمام معیارهای پذیرش `data-model.md` را برآورده کند.

## فاز ۱: تولید سؤال + داوری + ارجاع‌دهی

### هدف

پیاده‌سازی حلقهٔ کامل تولید سؤال متنی و فرمولی (بدون شکل و تصویر، بدون ورودی تصویر، و بدون رابط وب کاربری؛ منحصراً از طریق CLI و REST API) برای دروس ریاضی، فیزیک و شیمی پایهٔ دوازدهم متوسطهٔ دوم در دو رشتهٔ ریاضی و تجربی.

### خروجی‌های مورد انتظار

- حلقهٔ Generator → Judge → Solver مطابق `question-generation.md` با ارزیابی مستقل Solver و داوری مستقل Judge
- ثبت و اتصال به موجودیت مستقل `source` برای آزمون‌های ورودی
- ارجاع‌دهی خودکار به کتاب درسی و سؤال‌های کنکور مرتبط
- ذخیرهٔ سؤال با تمام فیلدهای کنترلی (`status`, `judge_score`, `judge_reasoning`, `solver_matches_key`, `solver_agreement`, `verification_methods`, `reject_reason_codes`, ...)
- ثبت تاریخچهٔ تمام دورهای حلقه در موجودیت `generation_attempts`
- management command برای تولید دسته‌ای سؤال
- REST API پایه برای خواندن سؤال‌ها و نتایج

### معیار پایان فاز ۱ (بازنویسی)

۱. **آزمون طلایی (همیشه اجباری):**
   - مجموعه‌ای از سؤال‌های واقعی کنکور سراسری با کلیدهای رسمی منتشرشده به Solver و Judge داده می‌شود.
   - دقت Solver و Judge روی این مجموعه به‌طور مستقل اندازه‌گیری شده و نتایج در گزارش مستند می‌شود.
   - آستانهٔ قبولی دقت برای Solver و Judge: پیشنهاد (باز) — باید پیش از شروع فاز ۱ تعیین شود.

۲. **بازبینی نمونه‌ای انسانی (فقط اگر `require_human_verification` فعال باشد):**
   - بازبینی باید برای هر درس به‌صورت جداگانه (ریاضی، فیزیک، شیمی) انجام گیرد، نه یک نمونه‌گیری کلی ۲۰ تایی.
   - اندازهٔ نمونهٔ آماری و روش انتخاب تصادفی: پیشنهاد (باز).
   - *نکتهٔ مهم:* نمونهٔ کوچک برای برآورد و تعمیم دقت کافی نیست.

۳. **اگر تأیید انسانی غیرفعال باشد (`require_human_verification=false`):**
   - معیار قبولی صرفاً آزمون طلایی و متریک‌های خودکار سلامت حلقه است.
   - مستندات و خروجی‌های سیستم باید صریحاً بنویسند: «خروجی فاز ۱ تأیید خودکار هوش مصنوعی است و تأیید انسانی نشده است.»

۴. **تولید حداقل X سؤال approved برای هر درس (ریاضی، فیزیک، شیمی) — (مقدار X: باز).**

۵. **ارجاع معتبر به کتاب درسی و سؤال کنکور برای تمام سؤال‌های approved ثبت و ذخیره شده باشد.**

## فاز ۲: ورودی تصویر و پشتیبانی از سؤال‌های تصویردار (طرح کلی)

### هدف

کاربر بتواند تصویر سؤال یا حل استاد را آپلود کند و سیستم پاسخ ساختاریافته برگرداند؛ همچنین پردازش و پشتیبانی از سؤال‌های تصویردار (نمودار، شکل هندسی، مدار الکتریکی، ساختار شیمیایی) در این فاز آغاز می‌شود.

### خروجی‌های مورد انتظار (کلی)

- پردازش تصویر سؤال: تشخیص متن، فرمول، گزینه‌ها و شکل‌ها
- پشتیبانی و ورود سؤال‌های دارای تصویر از منابع
- حل سؤال با مدل زبانی و ارائهٔ راه‌حل گام‌به‌گام
- تشخیص و ساختاردهی حل دست‌نویس استاد

### معیار پایان (کلی)

- حل صحیح حداقل ۸۰٪ سؤال‌های آپلودشده.
- جزئیات پس از تکمیل فاز ۱ مشخص می‌شود.
